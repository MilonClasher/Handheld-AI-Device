Chapter II · Electrical assembly

Wiring & safety

Connect each module to the ESP32 Dev Kit V1 exactly as listed. All grounds must share a common ground. Keep the board unpowered while changing connections.

Critical: the joystick breakout may label its supply pin “5V”. Connect that pin to the ESP32 3V3 rail. GPIO35 and GPIO36 are not 5 V tolerant; a true 5 V joystick supply can put unsafe voltage on the analog inputs.

Wiring sanity checks

  • Check that SDA and SCL have not been swapped.
  • Confirm the INMP441 L/R pin is tied to GND as shown.
  • Use normally-open buttons from their assigned GPIO to ground.
  • Do not power a module from a pin whose voltage rating you have not verified.

  1. Install ESP32 board support in Boards Manager if it is not already available.
  2. Install the library versions above through Library Manager.
  3. Open the supplied firmware source and select the ESP32 board and connected serial port.
  4. Choose the exact partition scheme. The firmware stores raw recordings in LittleFS, so a suitable flash partition is necessary.
  5. Compile and upload. If upload fails, verify the selected port and board before changing code.
Storage note: the firmware mounts LittleFS and writes recordings to flash rather than keeping the entire recording in RAM. The configured partition is part of the design, not an optional performance tweak.

Chapter IV · Wireless provisioning

Bluetooth setup

Use Bluetooth to send the terminal your Wi-Fi name, Wi-Fi password, and API key settings. You do not need to edit the firmware or type these settings on the terminal itself. To open setup, hold MIC and SEND while powering it on.

  1. Install or open a BLE GATT client on your phone or computer.
  2. Power on the terminal while holding MIC and SEND together.
  3. Scan for ESP32-VoiceAI and connect.
  4. Open the writable characteristic shown below, then write the full text block as UTF-8 text with each setting on its own line.
  5. No END line is required; the firmware reads the recognized settings line by line. After writing, allow the device to reconnect to Wi-Fi.

Where to get your API keys

Create an account with the service provider and find its API or developer dashboard. For the default settings in this template, use an OpenRouter API key for chat and a Groq API key for speech-to-text. Create or copy the key from the provider's dashboard, then paste it after the appropriate label above. An API key is not your normal account password.

Keep credentials private. Do not paste real Wi-Fi passwords or API keys into screenshots, public repositories, or public issue reports. Some providers require billing or available usage before requests work. Check your provider's dashboard for current access and limits.

Chapter V · Normal operation

Operating states

The same two buttons do different jobs depending on the screen. Check the current display before pressing a control.

RecordingStop recording and transcribe——

Voice path: record → stop → review the transcript → SEND to ask the AI. If the transcript is wrong, use MIC on the review screen to discard it and record again.
Typed path: open the keyboard with the joystick press → navigate to keys → press to select → choose SND or press the physical SEND button to submit.

What happens during voice input?

Audio is captured at 16 kHz, mono, then written as raw 16-bit samples to flash. When recording stops, the firmware sends the audio to the configured transcription endpoint. The resulting text is shown for review before the chat request is made.

Chapter VI · Text entry

On-screen keyboard

Move the joystick to move the highlight. Press the joystick switch to select the highlighted character or action. The keyboard has an alphabet layout and a symbol layout.

Character keys

Number row, alphabet rows, or punctuation/symbol rows. Letters use the current caps state.

Action keys

CAP change letter case; SYM switch to symbols; SPC insert a space.

Edit & submit

DEL delete; AC run the firmware's autocorrect action; SEND submit the prompt.

Exit

Press physical MIC to leave the keyboard and return to the mic screen. This does not start a recording from the keyboard state.

Keyboard habits that prevent mistakes

  • Check whether the alphabet or symbol page is active before typing punctuation.
  • Use DEL to correct a typo before sending; the prompt buffer holds at most 128 characters.
  • Use the physical SEND button as a direct submit shortcut when needed.
  • Autocorrect is a convenience, not a guarantee. Review names, technical terms, URLs, and identifiers before submission.

Chapter VIII · Fault finding

Troubleshooting

OLED stays blank

Check 3V3 and GND first, then confirm SDA is GPIO21 and SCL is GPIO22. The firmware expects I²C address 0x3C. Inspect the solder joints and module pin labels.

BLE device does not appear

Power-cycle while holding MIC and SEND together to force setup mode. Confirm the board has power and scan for ESP32-VoiceAI. Check Serial Monitor at 115200 baud for startup messages.

Wi-Fi will not connect

Re-enter the exact SSID and password, including case and spaces. Check that the network is reachable from the device's location. If credentials were changed, reopen BLE setup and send a fresh configuration.

Recording starts but transcription fails

Check Wi-Fi first, then verify the speech API key, transcription URL, and model name. Keep recordings under 30 seconds. If LittleFS failed to mount, the firmware reports that voice recording will not work.

Voice is not recognized correctly

Check the INMP441 pin mapping (SCK 32, WS 25, SD 34), 3V3 supply, common ground, and L/R-to-GND connection. Reduce background noise and speak close enough to the microphone without covering it.

Typed input behaves strangely

Verify joystick VRx is on GPIO35, VRy on GPIO36, SW on GPIO33, and joystick VCC is connected to 3V3. Check that the joystick press switch shares ground with the ESP32.

Chat request fails while transcription works

Check the chat key on the API: line, then confirm the chat endpoint and model identifier are accepted by your provider. The speech and chat services may use different credentials and different endpoints.

Answer seems cut off

Press SEND on the answer screen to advance through the available pages. The firmware stores a bounded number of wrapped lines; content beyond its buffer cannot be displayed.

Compilation or upload errors

Confirm ESP32 board support is installed, select ESP32 Dev Module, install the required library families, and use the No OTA (2MB APP/2MB SPIFFS) partition scheme. Check the first compiler error rather than fixing later cascade errors.

Useful diagnostic order

  1. Power and wiring.
  2. Serial Monitor startup output.
  3. BLE configuration values.
  4. Wi-Fi connection.
  5. Provider key, endpoint, and model.
  6. Only then investigate firmware changes.

Chapter IX · Credentials & data

Privacy & security notes

  • Wi-Fi credentials and API keys are provisioned to the device. Treat the terminal as a device holding secrets.
  • Voice recordings are written to the device's LittleFS storage before being sent for transcription. Voice processing depends on the configured cloud service.
  • Typed prompts and transcribed speech are sent to the configured chat service when submitted. Do not enter private information unless you are comfortable sending it to those providers.
  • Provider terms, retention, billing, and model availability are controlled by the providers, not by the device.
Firmware security caveat: the supplied source uses WiFiClientSecure::setInsecure() in request paths. That disables TLS certificate verification. Encrypted transport alone does not authenticate the server in this configuration; do not treat it as suitable for sensitive use without correcting certificate validation.

Before sharing the project, remove real keys and passwords from configuration examples, serial logs, screenshots, and repository history. Rotate any key that has been exposed.
